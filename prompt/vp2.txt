## 4. Implement the Text Chat API

Add:

`POST /chat`

Follow the existing route-prefix and response conventions where practical. Document the final endpoint path in the README.

Example request:

{
  "message": "Namaste! Introduce yourself.",
  "session_id": "demo-session-001",
  "language": "hinglish"
}

Example successful response:

{
  "session_id": "demo-session-001",
  "reply": "Namaste! Main AwaazAI hoon. Aapki kya help kar sakta hoon?",
  "model": "gemini-2.5-flash"
}

The actual reply must come from Gemini, not a hardcoded response.

### Request validation

- `message` is required, must contain non-whitespace text, and must have a reasonable maximum length.
- Validate `session_id`; generate one when omitted if appropriate.
- Support `english`, `hindi`, and `hinglish`, while following the existing naming convention if one already exists.
- Reject invalid input with the project's existing standardized error format.
- Do not echo sensitive input in validation errors.

### Conversation history

Implement basic multi-turn conversations:

- Maintain a bounded, in-memory history keyed by session ID.
- Preserve conversation context between requests using the same session ID.
- Isolate different sessions.
- Limit stored turns and total history size.
- Prevent unbounded memory growth by limiting sessions and applying a documented expiration/eviction policy.
- Ensure concurrent requests for the same session do not corrupt conversation history.
- Do not persist conversation content to disk or the database.
- Explicitly document that in-memory sessions reset on restart and are not shared across multiple workers.

### Language behavior

The system instruction must tell Gemini to:

- Respond in the requested language.
- Understand English, Hindi, and natural Hinglish.
- Sound friendly, concise, conversational, and suitable for a future voice interface.
- Avoid claiming to have performed actions it has not performed.
- Follow the user's language preference unless the user requests another language.

Keep the system instruction separate from user-supplied messages.
