### Token handling

The existing backend returns a bearer JWT with a 30-minute expiry and does not implement refresh tokens.

Keep the token in memory by default. Do not introduce persistent localStorage token storage without a separately reviewed security decision.

Handle HTTP 401 responses by clearing in-memory authentication state and directing the user to sign in again.

Explain that reloading the browser loses the in-memory token, so the user may need to log in again.

Do not invent a logout endpoint. Provide a frontend sign-out action that clears the local session and redirects to login.

## 13. Existing Voice Testing Integration

Preserve and inspect the existing files under `Frontend/src/voice/` and the existing voice page.

The VoiceAgent service exposes:

- `GET /health`
- `POST /chat`
- `POST /chat/stream`
- `WS /stt/stream`
- `POST /tts/stream`
- `WS /voice/stream`

The existing WebSocket protocol requires a configuration message followed by supported text or binary audio frames.

The server may emit readiness, partial/final transcription, reply text, audio segment events, errors, and terminal completion events.

Read the actual protocol implementation before modifying the client.

Requirements:

- Preserve PCM16 microphone capture requirements.
- Preserve the expected sample-rate handling.
- Respect the existing audio framing protocol.
- Handle browser microphone permissions.
- Handle microphone denial and missing devices.
- Handle WebSocket close, reconnect, timeout, and protocol errors.
- Clean up tracks, audio nodes, sockets, and listeners on unmount.
- Prevent overlapping sessions.
- Show an explicit connection state.
- Process audio segments in the order required by the server.
- Handle non-fatal TTS errors separately from fatal turn errors.
- Never assume a response is complete before the server signals completion.

Do not replace a working voice client with a fake simulation.

### Voice status

Use:

`GET /api/v1/voice-agent/status`

This is an authenticated backend endpoint. Show its actual status in the interface.

Use the existing `VITE_VOICE_AGENT_WS_URL` configuration for the local voice socket, preserving the current loopback-only guard.

Important security constraint:

The VoiceAgent currently has no inbound authentication and is not yet connected to the authenticated agent configuration. Keep direct voice access restricted to local development. Do not expose the unauthenticated VoiceAgent service to public users or production deployments.

The backend does not yet issue voice tickets, and the voice pipeline does not yet apply each saved agent's system prompt and voice configuration.

Do not claim that per-agent authenticated voice testing is complete until the required backend integration has been implemented and verified.
