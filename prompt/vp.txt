## 4. Target Architecture

The VoiceAgent is the AI execution service, not the platform's user-management backend.

**Backend responsibilities**
- User authentication and authorization.
- Agent configuration and ownership.
- Database persistence.
- Platform APIs and coordination with the VoiceAgent.

**VoiceAgent responsibilities**
- Conversation orchestration.
- LLM provider integration.
- Conversation state and context management.
- Tool execution with explicit validation and authorization boundaries.
- Streaming STT and TTS.
- Audio buffering, cancellation and interruption handling.
- Structured errors, latency metrics and health reporting.

**Frontend responsibilities**
- Agent dashboard and configuration.
- Microphone access and audio playback.
- Conversation transcript and live status.
- Mute, stop and interruption controls.

The VoiceAgent must not independently trust client-supplied user IDs, permissions or agent ownership. Define a secure service-to-service authentication contract before exposing protected operations beyond local development.

## 5. Implementation Phases

### Phase 1 — Minimal working service
- Create a small, maintainable FastAPI application inside `VoiceAgent/`.
- Provide `GET /health` compatible with the existing Backend's health client.
- Add configuration validation, structured errors, request IDs and appropriate logging.
- Use port `8001` locally, leaving the existing Backend on `8000`.
- Add a dedicated Python virtual environment and minimal pinned direct dependencies.
- Add automated tests for health, configuration and error handling.
- Document exact PowerShell commands to install, run and test the service.

**Acceptance:** The service starts independently, `/health` returns the documented response, and tests pass.

### Phase 2 — Working text-based AI agent
- Integrate Gemini behind a provider interface.
- Create a conversation endpoint with input validation and structured output.
- Add bounded conversation history and explicit session handling.
- Handle provider timeouts, rate limits, invalid responses and missing credentials safely.
- Keep API keys in environment variables.
- Add mocked unit tests that run without paid API calls, plus an optional real-provider smoke test.

**Acceptance:** A test prompt receives an actual model response when valid credentials are configured; missing credentials produce a clear, safe error.

### Phase 3 — Streaming LLM and orchestration
- Add token streaming over an appropriate HTTP streaming or WebSocket interface.
- Implement cancellation when the client disconnects or stops a response.
- Introduce LangChain only where useful.
- Introduce LangGraph only when explicit workflow state, branching or multi-step execution justifies it.
- Add bounded context, timeouts, retry rules and per-session concurrency controls.
- Measure time to first token and total response latency.

**Acceptance:** Streaming works, cancellation stops unnecessary work, and parallel sessions do not corrupt each other's conversation state.

### Phase 4 — Streaming speech-to-text
- Compare available STT providers based on streaming support, Hindi/Hinglish accuracy, latency, pricing and licensing.
- Choose one initial provider using current documentation and explain the trade-offs.
- Define a provider-independent interface.
- Validate audio format, sample rate, frame size and supported encoding.
- Support partial and final transcripts when the provider permits.
- Handle end-of-speech detection, timeouts and stream termination.
- Test using mocked audio streams; add a real-device smoke test when credentials and hardware are available.

### Phase 5 — Streaming text-to-speech
- Compare TTS providers for streaming playback, natural Hindi/English voices, latency, interruption support, cost and licensing.
- Implement one provider first behind a clean interface.
- Define audio format and chunk contracts.
- Support cancellation and cleanup when speech is interrupted.
- Do not buffer the entire audio response if incremental playback is supported and appropriate.

### Phase 6 — Full-duplex conversation and barge-in
- Connect STT, LLM and TTS into a cancellable conversation pipeline.
- Let users interrupt the assistant while it is speaking.
- Cancel pending TTS and, where possible, ongoing LLM generation.
- Prevent stale audio chunks from playing after cancellation.
- Keep conversation state consistent when the user interrupts.
- Handle silence, background noise, duplicate events, disconnects and reconnection.
- Define and measure end-to-end latency and interruption response time.

### Phase 7 — Platform integration
- Connect the existing Backend's agent configuration and authenticated service contract to the VoiceAgent.
- Verify that only authorized agents can be executed.
- Add frontend integration only after the API and streaming contracts are stable.
- Test the complete browser microphone → STT → LLM → TTS → audio playback flow.
- Add operational limits, health checks, safe shutdown and deployment documentation.

## 6. Engineering and Security Rules

- Use asynchronous I/O for network and streaming operations where appropriate.
- Never block the event loop with long-running synchronous operations.
- Use explicit timeouts, cancellation handling and resource cleanup.
- Keep user sessions isolated.
- Validate all inputs and tool arguments.
- Do not execute arbitrary model-generated code or shell commands.
- Do not expose provider keys, raw credentials, sensitive transcripts or internal exception details in responses or logs.
- Avoid logging complete audio payloads or unnecessary personal conversation data.
- Use bounded queues and buffers to prevent unbounded memory growth.
- Do not introduce a database, vector store, RAG pipeline or multi-agent architecture until a concrete requirement justifies it.
- Do not add Redis or another service merely to follow a generic architecture pattern.
- Document any unavoidable provider-specific limitations.

- Add integration tests for actual service contracts.
- Run the complete existing VoiceAgent test suite after each meaningful change.
- Do not claim tests pass unless they were actually executed.
